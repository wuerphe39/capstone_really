# Gemini 실호출 확인 — 2026-10-23

모델 `gemini-3.5-flash-lite`(무료 구간 모델, 기본값)를 실제 API 키로 호출해 설명 경로를 확인했다. 키는 로컬 `.env`에만 있고 Git·문서에 없다(`.env`는 Git 제외). 이 노트북에서 한 확인이며, 이전 기록([rag_v2_real_integration.json](evidence/rag_v2_real_integration.json))의 후속 재확인이다.

## 보낸 데이터

- 합성 관찰의 파생 문장(`verify_gemini`, `verify_outing_gemini`)과, 앱 수준 확인에서는 **공개 음원(ESC-50) 시연 외출 1개**의 파생 사실 문장(예: "분석 표본은 15초입니다", 모델 창 수). **음원 파일, 웹캠 영상, 마이크로 녹음한 외출의 기록은 보내지 않았다.**
- 무료 구간의 입력은 Google 제품 개선에 쓰일 수 있다([요금 문서](https://ai.google.dev/gemini-api/docs/pricing)). 이번에는 개인정보가 없는 자료만 보냈다. 실제 기록(사용자 강아지)으로 설명을 요청할 때는 규칙 제공자를 쓰거나 유료 구간으로 바꾸는 선택을 해야 한다.

## 결과

| 확인 | 결과 |
|---|---|
| 잘못된 키(키 없이 한 사전 시험) | Gemini가 HTTP 400으로 거절 → `rule-fallback`으로 내려가 요약·권장 행동 정상 생성, 실패 이유 기록, 잘못된 키는 결과에 남지 않음 |
| 케어 제안(`scripts.verify_gemini`, 합성 관찰 2개) | `gemini:gemini-3.5-flash-lite`, MCP 검색 `ok`, 과거 관찰 #2 인용. 요약은 "원본과 전후 상황을 확인하고 자극 요소를 기록해 달라"는 조심스러운 문장이며 진단·단정이 없다 |
| 귀가 설명 3종(`scripts.verify_outing_gemini`: 세션·하루·보호자 의견) | 3/3 통과. 항목별로 실제 Gemini, 폴백 없음, 문장과 인용이 서버가 계산한 사실과 일치, 검색된 ID만 사용, 답변이 근거 문장과 일치, 기대 주제 포함 모두 `true`. 기록: [outing_gemini_verification.json](evidence/outing_gemini_verification.json) |
| 앱 수준(`start_demo.ps1 -Gemini`, 공개 음원 시연 외출, 질문 3개) | 3/3 HTTP 200, 제공자 `gemini:gemini-3.5-flash-lite:fact-selection`, MCP 검색, 폴백 없음, 인용한 관찰 ID가 모두 그 외출의 관찰(#2~4) 안에 있음 |

## 해석

- 귀가 설명에서 Gemini의 역할은 **서버가 계산한 사실 중 어떤 것을 근거로 고르는가**다(`fact-selection`). 문장은 서버가 만들어 그대로 보여 주므로 수치·문장이 바뀌지 않는다. 질문에 따라 고른 사실이 달라지는 것(예: 두 번째 질문은 "표본 시간"을 빼고 "후보 창"을 앞에 둠)은 확인했지만, 세 답의 "다음 확인 제안"은 같았다. 이 부분은 검색된 기록으로 만든 고정 안내에 가깝다.
- "지난 외출과 비교해 주세요"는 시연 외출끼리는 입력 조건이 달라 비교 문장이 나오지 않았다(비교 불가를 별도 안내). 설계대로다.
- 케어 제안(자유 문장 생성)은 인용 ID의 범위는 검사하지만 문장별 수치·인과의 사실성을 모두 검증하지는 않는다. 개발자가 만든 합성 사례 몇 개의 연동 확인이며 독립적인 품질 평가가 아니다.
- 키는 Google의 새 형식(점이 한 개 있는 53자)이었으며 `x-goog-api-key` 헤더로 정상 동작했다.

## 같은 점검에서 고친 것

`scripts/verify_outing_gemini.py`의 합성 보고서가 현재 보고서 형식(YAMNet 모델 이름, 분석 창 수, 시연 표본 필드)이 없어 `KeyError`로 호출 전에 실패했다. 현재 형식에 맞게 필드를 채웠다.
